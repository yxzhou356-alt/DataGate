# Local detector evaluation

Install spaCy and the local `en_core_web_sm` model during setup, never through a
runtime request. The gateway must block policies requiring PERSON if detection
is unavailable. Merely disabling the detector must not bypass required policy.

From `backend/`, using the project's Python environment:

```bash
python -m evaluation.run --split development --output runtime/ner-development.json
python -m evaluation.run --split heldout --output runtime/ner-evaluation.json
```

The 56 manually annotated synthetic examples comprise 16 development and 40
heldout examples. Labels are authored explicitly, not generated by the model.
The evaluation compares existing EMAIL/PHONE rules with the same rules plus
local pretrained PERSON NER. No training or fine-tuning is performed.

Scores require exact category and code-point span matches. Partial names count
as a false positive and a false negative. Undefined precision/recall is `null`.
Reports include real counts, per-category metrics, model/config fingerprint,
corpus hash, revision/dirty state, time, and error example IDs/offsets. They do
not include input messages or raw entity values. A missing model produces an
explicit `model_unavailable` report, no fabricated hybrid score, and exit 2.

This small convenience sample does not establish real-world coverage or privacy.
Do not reuse measured results after changing the model, corpus or detector.

## Recorded heldout run

`heldout-results.json` records an actual run with spaCy 3.8.16 and
`en_core_web_sm` 3.8.0 on 40 examples (25 PERSON, 4 EMAIL, 4 PHONE gold spans).

| Detector/category | TP | FP | FN | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Rules-only PERSON | 0 | 0 | 25 | undefined | 0% | 0 |
| Rules + NER PERSON | 21 | 3 | 4 | 87.5% | 84% | 0.8571 |
| Rules + NER EMAIL | 4 | 0 | 0 | 100% | 100% | 1.0 |
| Rules + NER PHONE | 4 | 0 | 0 | 100% | 100% | 1.0 |

Hybrid micro F1 is 0.8923. The small EMAIL/PHONE support is insufficient for a
general accuracy claim. PERSON errors include ambiguous short names, lowercase
and multipart-name boundary mismatches, and a label word mistaken for a name.
The JSON identifies errors by example ID and offsets, alongside source hashes,
run time and revision/dirty state. It was generated from a working tree with
uncommitted feature changes; it is not a result for the unchanged baseline.

`pseudonymize_messages` operates before optional message hiding. It resolves
equal normalized surfaces within a request, not real-world aliases. Numbering
is source-order deterministic per category and resets between requests. Resolve
overlaps with EMAIL > PHONE > PERSON before calling it. The token mapping stays
local to the function; do not serialize it into receipts or event metadata.
